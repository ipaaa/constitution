**最後是這一節真正的產出，而它不在任何一個 PR 的 diff 裡。**

`056` 與 `012` 在同一天、各自獨立，收斂到同一組問題。一個自動檢查的自我保護必須分別回答三件事：

1. **它到底有沒有真的去比對？**（`scanned` 非零，否則 exit 2）
2. **它拿來比的基準可信嗎？**（基準必須來自規則指名的來源；讀不到就失敗，**不退回預設值**，exit 3）
3. **它比的是不是該比的那個對象？**

第三個問題有三種形式：**肯定式斷言吃「多重滿足者」**（要求的字串有多個產生點，該負責的壞掉時由另一個頂替）、**否定式斷言吃「多重施用者」**（豁免按字串值發而非按產生者發）、以及 **G-7 那種「滿足者散在三個檔而檢查只數了檔數」**。

`056` 的 reviewer 把三者收成一句：**檢查確認了「有人」滿足那個性質，從來沒有確認「該負責的那個對象」滿足它。** 並在最後一輪回答「有沒有第四種形式」時明說沒有，**另外點名兩個相鄰但不同的軸（代理軸、時刻軸），理由是「把它們混進同一句話，下一輪就會有人以為問過了」。**

還有幾句值得留著：

- **「我們選擇不加守衛」不是「它已經一致」。**（012 的 F22，一個 ✓ 把兩者混為一談）
- **「沒有呼叫者」不是「沒有缺陷」。**（012 的 O9：`acBlock('AC-7')` 舊版回傳 229,649 字元、洩漏 28 個標題，從未誤動只因為唯一的呼叫者是 AC-1）
- **deny-list fails open，allow-list fails closed——同一份名單，極性決定它往哪邊倒。**
- **同一份不完整的名單，放在掃描面上是洞，放在交叉檢查上是噪音。**
- **區段範圍的檢查要用「把目標放到區段外緣」來驗，不能用「放在區段內會通過」來驗。**
