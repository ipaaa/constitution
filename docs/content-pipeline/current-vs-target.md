## 一句話

現在網站的內容怎麼上線，**沒有人在把關，也沒有人看過**。目標是讓每一次上線都有人按過同意。

## 目標狀態

```
①  寫作者（法學者・編輯）
    │
    │  在試算表填內容。status 欄改不到。
    ▼
   ┌──────────────────────────────────┐
   │  SSOT 試算表  ← 唯一真相           │
   │                                  │
   │   Track 1_history    歷史軌       │
   │   Track 2_discussion 討論軌       │
   │   site_tldr          網站摘要區塊  │
   └──────────────────────────────────┘
    │
    ▼
②  編輯台核可
    │
    │  把 status 改成 Approved。只有編輯台能改這一欄。
    │  退稿就改成 Rejected，並填退稿原因。
    ▼
③  工程師手動執行同步     ← 重點：不是自動，要有人按
    │
    ├─── 檢查資料 ──── 有問題？
    │                   │
    │                   ▼
    │              整份停下。一個檔案都不寫。
    │              列出是哪幾筆、哪一欄、錯在哪。
    │
    ▼ 全部通過才繼續
   src/data/*.json
    │
    ▼
④  開 PR
    │
    ├─ diff  ＝ 這次要發布什麼的完整清單，逐字可看
    └─ Vercel 自動產生預覽網址 ← 編輯台在這裡看實際畫面
    │
    ▼  有人看過並同意
⑤  合併 → 部署
    部署只讀已存檔的資料，不再抓試算表。
```

**四個關鍵設計，各自擋掉一種事故：**

| | 設計 | 擋掉什麼 |
|---|---|---|
| 1 | 部署不執行同步 | 沒人看過的資料自己上線 |
| 2 | 資料有問題就整份停下 | 壞資料混進去（15 筆貼歪就是這樣上線的） |
| 3 | 只收 `Approved`，空白不算 | 沒審過的內容溜出去 |
| 4 | 上線前一定要有人看過 diff 和預覽 | 測試字串、佔位摘要、虛構出處 |

## 差距表

| # | 差距 | 現在 | 目標 | 誰做 | 對應施工項目 |
|---|---|---|---|---|---|
| 1 | **部署會自動同步** | `build = sync && next build`，每次部署都重抓試算表 | 部署只讀已存檔資料 | 工程 | `design.md` 第七節第 8 項 |
| 2 | **沒有資料驗證** | 有問題只印警告，繼續寫入 | 整份停下，不寫任何檔案 | 工程 | 第七節第 7 項 |
| 3 | **Track 1 沒有把關** | `status` 空白也放行 | 只收 `Approved` | 工程 | 第七節第 7 項 |
| 4 | **同步不認識 `site_tldr`** | 該分頁的內容到不了網站 | 讀取並組回網站要的格式 | 工程 | 第七節第 7 項 |
| 5 | **兩張試算表** | `收集區` 與 `Editor` 並存，內容不一致 | 只留一張，`Editor` 封存 | 人工 | 第七節第 10 項 |
| 6 | **上線無人審閱** | 直接部署 | 開 PR，看 diff 與預覽網址 | 工程＋編輯台 | 第七節第 9 項 |
